The internal working tree contained ongoing notebook edits at the time of

## Reconstructed-trajectory source

The restricted project stores reconstructed trajectories as serialized Python
objects in a private shared collection. Those objects are built by the
upstream internal notebook `notebooks/00_save_3d_reconstructions.ipynb`.
Neither the private collection URL nor the pickle files are public
dependencies, because they can expose opaque metadata and cannot be audited
safely on GitHub.

For this release the private collection was read once in the restricted
environment. Only the selected numeric reconstructed position array was
retained. Horizontal coordinates were translated to a per-dive local origin,
depth was expressed as a positive metric coordinate, and source labels were
replaced by release-local sequential tokens. Each public NPZ contains exactly
one float64 array named `xyz_m`; phase bounds and non-identifying analysis
metadata are recorded separately in `data/dswp/trajectory_index.csv`.

This makes the reconstructed paths reproducible inputs for the paper analyses
without implying that the upstream raw-to-trajectory calculation can be
rerun publicly. A data steward should retain the private crosswalk and export
log outside this repository.

The public code is a refactoring, not a wholesale copy. It removes:

- environment-specific and absolute paths;
- direct loading of raw tag structures;
- private storage links;
- exploratory notebook output and abandoned analyses;
- dependencies on whale names or unpublished field metadata; and
- opaque intermediate objects.

It adds explicit schemas, validation, deterministic configuration, and
dataset-specific provenance documentation.

## Reproducibility boundary

The production pipeline begins from approved derived tables and reconstructed
trajectories. Raw-to-derived signal processing remains documented as upstream
provenance but is not executable from the public release because the raw inputs
are not included.

Each distributed derived file must appear in `data/manifest.csv` with:

- its dataset and analytical role;
- a short content description;
- row count and schema version;
- SHA-256 checksum;
- whether it is an input or generated output; and
- the approval status for public release.

The manifest is generated by `scripts/build_data_manifest.py`. Every current
input is marked `steward_review_required`; that value should be changed only
through the documented data-owner approval process, not merely because the
automated safety audit passes.

## Versioning

For a paper release, record:

1. the manuscript version or DOI;
2. the repository commit;
3. the derived-data bundle version;
4. the environment lock or container digest; and
5. the archival DOI.

This makes later corrections possible without silently changing the data or
analysis associated with the published article.
